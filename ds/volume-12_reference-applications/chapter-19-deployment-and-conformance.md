# Chapter 19: Deployment & Conformance

**Volume XII — Reference Applications · Working Draft v0.1**

## 19.1 Purpose

How reference applications map to deployment profiles and certification.

## 19.2 Deployment Profiles

- **Personal Wearable:** daily utility, fitness, media.
- **Productivity:** workspace applications (Chapters 4, 18).
- **Industrial:** logistics, maintenance.
- **Medical:** health, wellness, medic.
- **Education:** collaboration, spatial tools.
- **Automotive:** HUD Assist, vehicle dashboard.
- **Smart Home:** Ambient Aura, home control.

Profile requirements follow Volume X, Ch 18.

## 19.3 Certification

- Certified applications MUST meet Volume IX, Ch 20 requirements.
- Certification profiles distinguish consumer, enterprise, medical, industrial.
- Accessibility verification is mandatory (Volume X, Ch 6).

## 19.4 Resource Budgets

- Each application operates within energy budgets (Volume IV, Ch 13).
- Minimal hardware tiers are power-optimized.
- Enhanced tiers add capability without changing application code.

## 19.5 Compliance Declarations

- Applications declare their certification profile.
- Declarations are machine-readable (Volume VII, Ch 20).
- Declarations are auditable.

## 19.6 Reference Application Registry

- Reference applications are maintained in the ecosystem registry (Volume X, Ch 11).
- They serve as conformance baselines (Volume X, Ch 9).
- They are used in training (Volume X, Ch 15).

## 19.7 Conformance

A conformant deployment MUST declare a profile and meet its referenced requirements.
