# Chapter 2: Standards Organization

**Volume X — Ecosystem Governance, Compliance & Certification (EGCC) · Working Draft v0.1**

## 2.1 Organizational Structure

The standards organization defines roles, responsibilities, and decision-making processes.

## 2.2 Committees

- Architecture Committee.
- Hardware Committee.
- MeshOS Committee.
- Protocol Committee.
- Security Committee.
- Interaction Committee.
- AI Committee.
- Certification Committee.

## 2.3 Architecture Committee

- Owns the system architecture (Volume II).
- Reviews cross-cutting changes.
- Maintains the Reference Architecture Repository (§1.5).

## 2.4 Hardware Committee

- Owns hardware standards (Volume III, 3A).
- Reviews module and connector specifications.
- Maintains sample hardware designs.

## 2.5 MeshOS Committee

- Owns operating system behavior (Volume IV).
- Reviews kernel and service interfaces.
- Maintains the MeshOS reference runtime.

## 2.6 Protocol Committee

- Owns the protocol specification (Volume VIII).
- Reviews message schemas and profiles.
- Maintains the Protocol Registry (§1.5).

## 2.7 Security Committee

- Owns security requirements.
- Oversees vulnerability handling (Chapter 12).
- Reviews trust anchors and algorithms.

## 2.8 Interaction Committee

- Owns interaction standards (Volume VI).
- Reviews semantic interactions.
- Maintains the Interaction Registry (§1.5).

## 2.9 AI Committee

- Owns AI and cognitive standards (Volume VII).
- Reviews model interfaces and orchestration.
- Maintains the Ontology & Knowledge Repository (§1.5).

## 2.10 Certification Committee

- Owns certification processes (Chapter 6).
- Approves conformance test suites (Chapter 8).
- Accredits certification laboratories.

## 2.11 Decision-Making

- Decisions follow documented consensus processes (Chapter 14).
- Committees report to the Standards Council.
- Records are public and auditable.

## 2.12 Conformance

A conformant standards body MUST maintain the committees and their documented responsibilities.
