# Chapter 9: Reference Implementations

**Volume X — Ecosystem Governance, Compliance & Certification (EGCC) · Working Draft v0.1**

## 9.1 Purpose

Defines official reference artifacts. Reference implementations are normative for behavior but not necessarily production-ready.

## 9.2 Reference Artifacts

- MeshOS reference runtime.
- Capability registry.
- Interaction engine.
- Protocol stack.
- SDK.
- Sample hardware.
- Example applications.

## 9.3 MeshOS Reference Runtime

- Canonical behavior for MeshOS services (Volume IV).
- Basis for conformance testing (Chapter 8).
- Open and auditable.

## 9.4 Capability Registry

- Canonical capability definitions (Volume V).
- Version histories maintained.
- Shared by the ecosystem (§1.5).

## 9.5 Interaction Engine

- Canonical interaction processing (Volume VI).
- Reference recognizers and mappings.
- Reference Interaction Library (Volume VI, Ch 18).

## 9.6 Protocol Stack

- Canonical protocol behavior (Volume VIII).
- Reference adapters for all transports.
- Interoperability test base (Volume VIII, Ch 19).

## 9.7 SDK

- Developer-facing libraries (Volume IX).
- Example-driven documentation.
- Certification test integration.

## 9.8 Sample Hardware

- Reference module designs (Volume III, Ch 17).
- Basis for hardware conformance.
- Not production-optimized.

## 9.9 Example Applications

- Reference Applications (Volume IX, Ch 19).
- Demonstrate conformant patterns.
- Used in training (Chapter 15).

## 9.10 Governance

- Reference implementations are committee-maintained.
- Changes follow the lifecycle (Chapter 3).
- Coverage is tracked on the Conformance Dashboard.

## 9.11 Conformance

A conformant reference implementation MUST faithfully reflect its specification and be versioned.
